TYPESAFE + OPENAI COMPATIBLE JUDGMENT PROXY
Implemented and checked: 2026-09-16. Independent Cerebras-backed implementation.
Canonical specification; api_references.txt is a pointer to this file.

1. SHARED HTTP CONTRACT

Base URL: http://127.0.0.1:3000
POST /v1/systemone
POST /v1/chat/completions
Authorization: Bearer <PROXY_API_KEY>
Content-Type: application/json

A distinct proxy credential of at least 16 characters is required. Never send the
Cerebras key as the proxy credential. Only uncompressed JSON is accepted. Unknown
fields, unsupported schema constraints and duplicate JSON object keys are rejected.
Every response has a server-generated x-request-id. No public streaming or partial
answers. Unsupported routes and methods return 404; there is no models endpoint.

2. TYPESAFE ENDPOINT

POST /v1/systemone
Exact request fields:
  model: qwen-3.8-27b | gpt-oss-120b | jev-latest
  state: string | JSON object | JSON array
  questions: nonempty object mapping caller IDs to question objects

jev-latest is an explicit compatibility alias for CEREBRAS_MODEL (default Qwen).
It does NOT run Jev. Responses always name the actual Cerebras model. Unknown
models fail validation. All questions share state; each gets an isolated inference
call with its own rubric, without sibling questions or answers. Caller question IDs
are kept out of inference; they only map returned answers. IDs appearing naturally
inside caller state/instructions cannot be removed by this rule.

Description values: string, object, array or null; nested values can be any finite
JSON value. This deliberately accepts the structured forms in the primitive guides,
which are broader than parts of the API page. Standalone numbers/booleans are not
accepted as description values. State cannot be null. Unknown question fields fail.

Choice question:
  {type:"choice", instructions:Description, criteria:{label:Description,...}}
  2..255 distinct labels; null descriptions are supported.
Answer:
  {type:"choice", choice:string, probabilities:{label:number,...}, confidence:number}

Score question:
  {type:"score", instructions:Description, criteria:[Description,...]}
  2..10 levels, ordered from index 0 to N-1.
Answer:
  {type:"score", score:number, legend:{"0":Description,...},
   probabilities:{"0":number,...}, confidence:number}

Noul question:
  {type:"noul", instructions:Description,
   criteria?:{true?:Description, false?:Description}}
Answer:
  {type:"noul", noul:number}
  noul is an estimated probability in [0,1], not a boolean or confidence interval.

Response:
  {model:string, answers:{caller_id:Answer,...},
   usage:{input_tokens:integer, output_tokens:integer}}
Usage sums actual provider counters across the question calls, including repeated
state input. All requested answers succeed or the entire request returns an error.

Example (synthetic request and answer):
Request:
{"model":"jev-latest","state":"Please return the duplicate payment.",
 "questions":{"refund":{"type":"noul","instructions":"Is money requested back?"}}}
Response:
{"model":"qwen-3.8-27b","answers":{"refund":{"type":"noul","noul":0.9}},
 "usage":{"input_tokens":100,"output_tokens":9}}

Local numerical policy (not an assertion of TypeSafe's undisclosed implementation):
- Choice/Score values must be finite, in [0,1], and cover exactly every criterion.
- sum > 0 and abs(sum-1) <= 1e-6; normalize only this accepted rounding drift.
- Choice selects argmax; ties use code-unit-sorted label order, independent of the
  caller's insertion order. No locale sorting.
- Score is sum(index * probability[index]); fractional values are retained.
- Legend is reconstructed from the caller's criteria, never generated by the LLM.
- Confidence is 1-H(p)/ln(N), H=-sum(p*ln(p)), with 0*ln(0)=0. Uniform gives 0,
  point mass 1. Clamp derived floating-point excursions only within 1e-12.
- No rounding, missing-value filling or semantic repair. These are model-written
  estimates, not calibrated outcome probabilities. TypeSafe confidence parity is
  explicitly not claimed.

3. OPENAI CHAT COMPLETIONS ENDPOINT

POST /v1/chat/completions
Exact request fields:
  model: qwen-3.8-27b | gpt-oss-120b (no Jev alias on this route)
  messages: 1..64 entries of {role:system|developer|user|assistant, content:string}
  response_format:
    {type:"json_schema", json_schema:{name:string, strict:true, schema:object,
                                     description?:string}}
  stream?: false
  n?: 1

At least one user message is required. Name is 1..64 ASCII letters, digits, _ or -.
Context goes in ordinary messages; no state/questions envelope hidden in content.
The contract is a normal strict JSON Schema in the supported subset below.

Full conversational role semantics are not claimed: client role labels and order
are preserved in serialized evaluation data under one upstream user message. The
server owns the single upstream system message and rubric. This deliberate
judgment-oriented boundary avoids provider chat-template restrictions and does
not allow a client message to disable the output gate. Descriptions in the schema
and json_schema.description supply evaluation rubrics; title/name are annotations.

Rejected: response_format text/json_object, unconstrained chat, streaming, tools,
function/tool roles, multimodal content parts, reasoning controls, sampling/token
controls, logprobs, storage and any other unknown request fields. They return
400 invalid_request, never silently drop requested behavior.

Example request:
{
  "model":"qwen-3.8-27b",
  "messages":[{"role":"user","content":"Please refund the duplicate charge."}],
  "response_format":{"type":"json_schema","json_schema":{
    "name":"routing","strict":true,
    "schema":{"type":"object","properties":{
      "department":{"type":"string","enum":["billing","technical","other"]},
      "refund":{"type":"number","minimum":0,"maximum":1,
                "description":"Estimated probability that a refund is requested."}
    },"required":["department","refund"],"additionalProperties":false}
  }}
}

Synthetic response:
{
 "id":"chatcmpl-example","object":"chat.completion","created":1789596000,
 "model":"qwen-3.8-27b",
 "choices":[{"index":0,"message":{"role":"assistant",
   "content":"{\"department\":\"billing\",\"refund\":0.9}","refusal":null},
   "finish_reason":"stop","logprobs":null}],
 "usage":{"prompt_tokens":100,"completion_tokens":9,"total_tokens":109}
}

Actual IDs are unique and created is current Unix seconds. Content contains ONLY
the requested JSON object as text, not a nested model/answers/usage wrapper.
Usage is actual upstream usage; reconstructed public text is not retokenized.
Constants-only schemas need no inference and return zero usage. Errors never
pretend to be successful assistant messages. Actual OpenAI SDK create/parse and
error-class compatibility is exercised by the test suite.

4. OPENAI SCHEMA SUBSET AND NUMERIC CODEC

Every node declares one type. Root must be object. Accepted keywords by type:
- All: type, description (<=8192 characters), title (<=256 characters).
- object: properties, required, additionalProperties:false. Every property must
  be required exactly once. Closed empty objects are valid.
- array: prefixItems:[schemas...], items:false. Fixed-length tuples only, <=255
  elements. Empty tuples are valid. Homogeneous/variable-length arrays rejected.
- string: enum or scalar const required. No arbitrary generated strings.
- number/integer: enum, scalar const, or BOTH minimum and maximum. Variable bounds
  must be finite and each absolute value <=1,000,000; integer range must contain
  a safe integer. Enum/const numbers must match declared type and optional bounds.
- boolean: optional enum/const, otherwise false/true.
- null: optional matching enum/const, otherwise null.

Enums have 1..255 unique homogeneous scalar entries matching type; string literal
values <=256 characters. Const is scalar and must satisfy any enum and bounds.
Unknown/inapplicable keywords rejected: $ref/$defs, unions, patterns, formats,
composition/conditionals, defaults, arbitrary additional properties, min/maxItems,
string length constraints and recursive schemas. No remote resolution or eval.

Limits: depth 10 (root=1), 500 total object properties, 500 variable enum entries,
255 numeric slots, 64 KiB serialized schema. Property names 1..256 UTF-8 bytes.
A constant consumes no slot. A boolean/enum consumes one bounded integer index;
a variable number consumes one bounded numeric slot. Object/array/leaf descriptions
are retained as rubric context. Output reconstruction uses declared literals and
validated numeric slots only. Schema annotations are not copied into the output.
The provider rubric spells out each enum/boolean selection as {index,value}
(zero-based), rather than requiring the model to infer positions from a label list.
This is an internal prompt clarification; public schemas and decoding are unchanged.

All OpenAI schemas use one compact inference call. No special rich-judgment schema
recognition is implemented: generic fields named probabilities/score/confidence
have only their declared schema constraints. Use /v1/systemone for normalized
probability distributions and locally derived TypeSafe-style answers. Generic
schema fields are not asserted to be independent of each other.

5. PROVIDER AND OUTPUT GATE

Native fetch calls https://api.cerebras.ai/v1/chat/completions directly, with the
server's CEREBRAS_API_KEY and X-Cerebras-Version-Patch:2. No client-selected provider
URL or model fallback. Default Qwen reasoning_effort:none; GPT OSS low, with parsed
reasoning. temperature:0, stream:false, max_completion_tokens:4096, no tools.
GPT OSS may generate internal reasoning; it is discarded, and counts can include it.

Every inference requests exactly {"p":[numeric slots...]} with a closed strict root
and fixed tuple prefixItems/items:false. Even a Noul uses a one-element array.
No custom JavaScript/DSL or arbitrary code execution. Selection indices map to
caller-declared values locally. This is the compressed intermediate representation.

Gate: bounded duplicate-aware JSON parse; validate completion envelope, exactly
one choice, finish_reason stop, content string, no non-null refusal/tool/function
calls, valid nonnegative safe-integer usage; parse content with duplicate checks;
require exactly p; validate tuple length, finite numbers, ranges, integer slots;
check TypeSafe distributions; reconstruct/derive fresh output; bound final bytes.
Provider extras such as reasoning/IDs are not forwarded. Errors/prose/invalid
values/truncation never become success. Invalid output has no automatic repair.

This prevents arbitrary provider-generated prose from entering the public answer.
It does NOT prove that malicious context cannot influence allowed choices/numbers
or encode sensitive information in them. Caller-supplied literals/legends may be
returned exactly where the contract specifies. Do not put secrets into context
that a caller is not authorized to learn. See ../security.md.

6. LIMITS, LIFECYCLE AND ERRORS

HTTP request/upstream response: 256 KiB each. JSON tree depth: 32, counting root as 1 (including scalar leaves).
Final serialized public response: 512 KiB. TypeSafe questions: 1..32; serialized
questions <=64 KiB. Question IDs and Choice labels: 1..256 UTF-8 bytes.
Serialized upstream body: <=48,000 UTF-8 bytes before sending. This conservative
input bound leaves context headroom; inputs are never silently truncated.
Whole-request deadline: 15 seconds including queueing/body/inference.
Global provider concurrency: 4; pending jobs: 32. All jobs preflight and admission
is atomic; overload dispatches none of that request. These are local demo limits.

Client disconnect/deadline cancels queued and active work. A fatal job cancels
siblings. Shutdown aborts active controllers. Completed work before cancellation
can still be billed. No automatic retries, fallback or repair. Provider error
bodies/Retry-After headers are not relayed. Unknown provider errors are sanitized.
Upstream 401 is reported as provider_authentication_failed (HTTP 502), distinct
from the client's proxy credential failure (HTTP 401). Checked 2026-09-17 against
https://inference-docs.cerebras.ai/console/api-keys and https://docs.typesafe.ai/api.
The local demo names the affected provider/environment setting and stops dispatch
on credential rejection or rate limiting, retaining already dispatched results.

OpenAI error body:
{"error":{"message":"Safe summary","type":"invalid_request_error",
          "param":null,"code":"invalid_schema"}}
TypeSafe error body (local policy; exact upstream body is undocumented):
{"error":{"message":"Safe summary","code":"invalid_request",
          "request_id":"server-generated-id"}}

HTTP (TypeSafe / OpenAI)   code
400 / 400                 invalid_json
422 / 400                 invalid_request
400 / 400                 invalid_schema (OpenAI schema path)
401 / 401                 unauthorized
404 / 404                 not_found
413 / 413                 request_too_large
415 / 415                 unsupported_media_type
429 / 429                 rate_limited
529 / 503                 overloaded
500 / 500                 internal_error
502 / 502                 provider_unavailable
502 / 502                 provider_authentication_failed
502 / 502                 invalid_provider_output
504 / 504                 deadline_exceeded

OpenAI type: authentication_error for 401, rate_limit_error for 429, server_error
for 5xx, otherwise invalid_request_error. Messages/codes are fixed safe strings.
No raw provider body, prompt, state, credential or question ID is logged by default.
Logs contain safe server IDs, status, duration, model, call count and token usage.

7. MEASUREMENT AND COMPATIBILITY EVIDENCE

npm run benchmark: local HTTP plus upstream stub (synthetic tokens, zero cost).
npm run benchmark:live: actual Cerebras calls, safe numeric timing/usage metadata.
Reports include p50/p95/p99, successful latency separately from failures, sample
counts, concurrency, warmup, provider/queue timings, tokens/s definitions, input/
output usage and dated estimated USD. Warmup is excluded from measured latency
and included in whole-run cost. Missing usage makes cost incomplete, not zero.
See ../../examples/README.md for exact methodology.

Qwen first live verification: seven examples passed structural gates; twelve
measured benchmark calls succeeded. Some example judgments were wrong. GPT OSS
and maximum-size live payloads were not tested. Do not infer quality, calibration,
full API parity or production throughput from wire-valid responses.
